# Журнал использования AI

- Исходная папка содержала только пример PyCharm `main.py`. Он сохранён в `docs/original_main.py.txt`; рабочий entrypoint теперь импортирует FastAPI.
- Весь новый код API, бота, тестов и документации создан AI-ассистентом Codex по подробному заданию пользователя. Самостоятельно написанные пользователем части и затраченное им время неизвестны.
- Инструменты: Codex, терминал, Python, pip, pytest, HTTPX; официальная документация SQLAlchemy и Pydantic.
- Окружение: системный Python 3.14.4; дополнительно найден Python 3.12.3 в Snap. Доступ к PyPI из терминала отсутствует, зависимости удалось установить из локального pip-кеша.
- Реальная ошибка AI: в первой версии валидации использовались только `max_digits=12` и `decimal_places=2`, но сообщение бота обещало максимум 9999999999.99. Тест показал, что целая сумма 10000000000 принималась: ограничение десятичных знаков не резервирует два разряда для целой суммы. Исправление: явное `le=Decimal("9999999999.99")` для денежных входных данных; тот же тип используется ботом.
- Дополнительная проблема окружения: запуск API-тестов остановился при создании AnyIO portal, до первого HTTP-запроса. Причина и итог проверки описаны в `VERIFICATION.md`.

## Редактируемый текст для части 4 (7 предложений)

Для выполнения задания я использовал(а) AI-ассистента Codex, терминал, pytest и официальную документацию SQLAlchemy и Pydantic.
Полезными были запросы «создай простой FastAPI API и aiogram-бот, работающий только через HTTP» и «проверь точность денежных сумм, границы месяцев, частичный PATCH и каскадное удаление».
Весь новый код API, бота, тестов и начальной документации в этой версии создан AI по моему техническому заданию.
Мои самостоятельно написанные или переработанные части: [SAMOSTOYATELNO NAPISANNYE CHASTI]; фактическое время моей работы: [CHASY].
Реальная ошибка AI заключалась в том, что `max_digits=12` и `decimal_places=2` не ограничивали целую сумму обещанным максимумом 9999999999.99, и тест с 10000000000 обнаружил это несоответствие.
Валидация исправлена добавлением явной верхней границы Decimal, а проверка сохранена в автоматических тестах API и бота.
Перед отправкой я проверю актуальный протокол `docs/VERIFICATION.md`, отдельно выполню проверку на Python 3.12 и вручную проверю Telegram с собственным токеном; эти действия нельзя считать выполненными только на основании генерации кода.
